# Try Ledger Demo

Demo starts with fictional activity in August, September, and October 2026. The first **Refresh now** brings in a small set of November examples. You can edit, link, and delete these records without affecting Apple Messages or a regular Ledger installation.

| Try this | What to look for |
| --- | --- |
| Open **Monthly spending** and change months | Pick a slice or category to open its confirmed expenses. Refunds, transfers, and card payments appear separately. |
| Click **Refresh now** twice | A fresh Demo picks up November records on the first refresh. A repeat scan of the same fixtures adds zero duplicates. **Data status** shows the scan range. |
| Search for **Fictional Duplicate Cafe** | Two transactions remain, one from Axis and one from ICICI. The repeated Axis SMS produces one record. |
| Open **Transactions → Possible duplicates** | Compare the two card receipts, link them as one payment, then open both original SMS. Unlink to restore both records. |
| Open **Needs Review → Review by recipient** | Find **Juniper Studio** in a single bank, select a few payments, and preview the change before confirming. Unselected payments stay in review. |
| Open **Needs Review → Why these need review** | Compare the bank and reason counts, then run the fictional SMS analysis. |
| Edit a category, reopen the app, and reimport | The saved correction stays in place. Try deleting a fictional row and using **Undo deletion** before quitting. |
| Open **View → Demo appearance** and **View → Demo window size** | Compare light and dark mode, plus compact and standard layouts. |

The sample SMS include posted purchases, refunds, transfers, card payments, uncertain debits and credits, a credit-card statement, and an advance debit notice. The statement and notice produce no transaction. The separate completed debit can still be imported.

When reporting a problem, include the Ledger version from **About Ledger Demo**, your macOS version, the fictional example, and the steps to reproduce it.
